## 4. 자동 분류 순서 (docClassify.ts)

1. 경로에 NAS 칸 폴더(`7. PLC TATA` 등)가 있으면 그 칸 — 번호와 이름 낱말이 맞을 때만.
2. 아니면 규칙 점수: 폴더 이름(3점) > 확장자(2점) > 파일 이름 낱말(1점). 가장 높은 칸.
3. 근거가 없으면 기타자료로 두고 "근거 없음 — 종류를 확인하세요".
4. 폴더째 올리면 안 파일들 제안 중 가장 많은 칸을 묶음 종류로.

예시 시험(18개 이름) 모두 기대한 칸으로 갔다 — 세션 스크래치 `cls.mts`.

## 5. 사내 AI 분류 (2026-10-30 구현)

- **종류는 사내 AI가 정한다.** 올리면 규칙 결과를 먼저 보여 주고, 사내 AI(`POST /api/ai/classify-docs`)가 14종류 중 하나와 이유·확신을 돌려주면 바꾼다. 규칙 결과·위 2~3장 근거는 AI에게 참고로 준다. 확신 0.6 아래는 '확인하세요'.
- 낱개 파일은 이름·경로·크기(+글자 파일 앞 1,500자), 폴더 묶음은 안 파일 경로 40개로 판단한다.
- 사람이 고른 줄은 AI가 덮지 않는다. AI가 없거나 실패하면 규칙 결과로 둔다.
- 시험: 공정 검토 pptx → 제안서, 레이아웃 pdf → 도면, 주간회의 xlsx → 회의록, CMOS·SRS_BACKUP이 든 폴더 → 현장 백업, 취급설명서·서보 매뉴얼 pdf → 매뉴얼(종류 설명을 같이 줄 때). 6건 약 4.7초.

## 6. 사내 AI를 더 붙일 자리

- 사내 AI: dy-linux SGLang(OpenAI 호환), `Llm:BaseUrl` = `http://192.168.11.146:18101/v1`, 모델 `qwen3.8-27b-fp8`. 이미 사양정리 초안(`SpecAi.cs`)·수담푸드 메뉴(Worker)가 쓴다. 키는 user-secrets `Llm:ApiKey`(로컬엔 아직 없음 — 서버는 401로 응답).
- 붙일 자리(우선순위):
  1. **규칙이 '근거 없음'일 때만** AI에게 묻기 — 파일 이름·폴더 경로·확장자 + (PDF·오피스면) 첫 장 글자 2천 자 → 14개 종류 중 하나 + 이유 한 줄. 규칙으로 되는 대부분은 AI를 부르지 않아 빠르고 비용이 없다. 응답은 '제안'으로만, 사람이 확인.
  2. **섞이는 확장자**(`.pdf`·`.pptx`·`.xlsx`·`.jpg`) — 이름만으로 애매하면 첫 장 글자로 판단(도면 pdf ↔ 매뉴얼 pdf, 회의록 pptx ↔ 사양서 pptx).
  3. 진행 일지 요약(주간·단계별) — 프로젝트 공유 일지를 모아 PM에게 "이번 주 부서별 한 일".
  4. 자료 검색 — 파일 첫 장 글자를 색인해 "IP 리스트 상도" 같은 자연어 검색.
- 원칙: AI는 제안만(자동 확정 안 함), 키 없으면 규칙만으로 동작, 고객 자료는 사내 서버(dy-linux)에만 보낸다.
