# 공장 허브 — 공장 단위로 앱을 모아 보는 화면 추천안 (2026-10-30)

시안: [공장 허브 시안.html](공장%20허브%20시안.html) · 관련 분석: 공정데이터 플랫폼 발표 분석(공유 노트 `process-data-platform-analysis.md`)

## 1. 왜 필요한가

- 사람마다 공장을 보는 이유가 다르다: 데이터를 넣는 사람(SRS 백업·MotoSim Cell), 레이아웃을 보는 사람, 사양을 보는 사람(영업·설계).
- 그런데 지금은 앱마다 각자 공장 트리를 가진다: SRS Analyzer(고객사→공장→부스→존 트리 + 프로젝트 추가), MotoSim(존 선택 → Cell 올리기), 공정 관리(plant 편집). 같은 공장을 보려면 앱을 옮겨 다니며 트리를 다시 펼쳐야 한다.
- 다행히 **데이터는 이미 같은 열쇠(plant.zone)로 묶여 있다.** 새 데이터를 만들지 않고 "모아 보기"만 하면 된다.

## 3. 방안 비교

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A. 공장 허브 화면 신설 (추천)** | 왼쪽 메뉴 '공장' → 공장 하나를 고르면 구성·프로젝트·앱 데이터·사양을 한 화면에. 각 앱의 상세 작업은 그 앱으로 **바로가기(존·프로젝트 지정)** | 앱을 다시 만들지 않음, 조회 전용이라 위험 적음, 레이아웃 탭을 나중에 꽂을 자리 | 앱 간 이동은 남음(바로가기로 완화) |
| B. 프로젝트 상세에 '공장' 탭 | 프로젝트 → 연결된 공장 데이터 | 기존 화면 재사용 | 공장 중심으로 보려는 사람(사양·레이아웃)에겐 거꾸로, 프로젝트 없는 데이터(MotoSim 49건)가 안 보임 |
| C. 앱들을 하나로 재구현 | SRS·MotoSim 기능을 공장 화면 안에 다시 만듦 | 이동 없음 | 공수 큼, 앱별 소유·배포가 꼬임, SRS는 별도 앱(:4175) |

→ **A안**: "공장이 첫 화면, 앱은 공장의 탭/바로가기". 앱 고유 작업(3D 분석, Cell 업로드)은 원래 앱에 둔다.

## 4. 화면 구성 (시안 기준)

1. **왼쪽: 공장 찾기** — 고객사별 공장 목록 + 검색 + 즐겨찾기(★), 공장마다 SRS·Cell·프로젝트 숫자 배지. 국내/해외 필터.
2. **머리: 공장 요약** — 고객사·공장명·위치, 숫자 카드(부스·존·로봇 / 연결 프로젝트 / SRS 측정·최근일 / MotoSim Cell·최근일 / 랩 테스트 / 사양서).
3. **탭**
   - **공정 구성** (기본): 부스→존 표에 앱 데이터를 칸으로 — 로봇 수, 연결 프로젝트, SRS 최근 측정, MotoSim 최신 Cell. 칸을 누르면 오른쪽 상세.
   - **프로젝트**: 이 공장에 연결된 프로젝트(상태·연결 존 수·어느 앱이 연결했는지) + "연결 후보"(이름에 공장명이 들어 있지만 연결 안 된 프로젝트).
   - **활동**: SRS 업로드·Cell 업로드·프로젝트 연결을 시간순으로.
   - **사양**: 사양서 분석 라이브러리에서 이 공장 폴더의 사양서·설비 이력(모델·PLC) — 사양서 분석 화면으로 바로가기.
   - **레이아웃**: 자리만(추후, 공정데이터 플랫폼 연계).
4. **오른쪽: 존 상세** — 로봇 목록, 프로젝트별 SRS 이력·Cell 이력, 버튼: `SRS Analyzer에서 열기` · `MotoSim에서 열기/Cell 올리기` · `공정 관리에서 편집`.

### 4-1. 구체화 시안(2차, 같은 날)에서 더한 것

- 실제 데이터 4개 공장(KIA HWASEONG 3·KIA GWANGJU 1·HYUNDAI JEONJU TRUCK·GMK Bupyeong) — 로컬 dyone + 사양서 분석 NAS 라이브러리 캐시.
- **개요 탭**: 존별 데이터 채움 지도(로봇·프로젝트·SRS·Cell 네 칸), **점검 필요**(자동 점검), 설치 설비 요약(도장 로봇·오프너·도장기·FGP, 사양정리·도면에서), 최근 활동.
- 자동 점검 규칙(시안): 로봇 미등록 존 / 프로젝트 이름의 공장과 연결된 공장이 다름(예: 광주1에 'DLP-25-107 기아 화성3 SG2 PE 티칭') / 랩 예산 프로젝트가 공장 존에 연결됨(DLY-23-004·DLY-24-004) / Cell 프로젝트 미지정 / 연결 후보 / 도장 존인데 SRS 없음.
- **앱 데이터 탭**: SRS 측정·MotoSim Cell·랩 테스트를 공장 단위 표로. 랩은 프로젝트 경유(등록일 2026-10-01은 이관일).
- **사양 탭**: 별칭(화성3·H3·화성#3 등)으로 찾은 사양서 목록(사양정리 판·고객 사양서·회의록 수) + 공정별 설비 이력 표.
- **존 상세**: '같은 공정 설비 이력'(존 이름 → 공정·외/내판 추정으로 사양 이력과 맞춤).
- 별칭 매칭은 틀릴 수 있다(부평 별칭에 2011 우즈벡 GM 폴더가 섞임, 화성3 후보에 '화성EVO EAST'). → 별칭 관리와 '아님' 처리가 필요.

## 5. 만드는 방법

- **새 표 없음(1차).** API 조회 하나: `GET /api/factories`(목록+배지 숫자), `GET /api/factories/{id}`(구성·숫자·프로젝트·활동). 읽기 전용 DbContext 그대로.
- **바로가기**
  - SRS Analyzer: 이미 `?zone={zoneId}&project={projectId}&measurement={id}` 지원(`dy-one-srs-analyzer/src/App.jsx`). DY ONE 임베드 페이지에 쿼리를 넘기기만 하면 됨.
  - MotoSim(내부 화면 `pages/motosim/MotosimPage.tsx`): **존 바로가기 쿼리가 없음** → `?zone=` 받아 그 존을 선택하는 정도의 작은 수정 필요.
  - 공정 관리(`E:\dy-one-process`): 바로가기 지원 여부 미확인 → 확인 후 동일하게.
- **권한**: 조회는 로그인 전원, 쓰기는 각 앱 권한 그대로(허브는 쓰지 않음).

## 6. 미리 풀어야 할 데이터 문제

1. **프로젝트 연결이 SRS에만 있음**: MotoSim Cell 49건은 project_id가 비어 있어 프로젝트 칸에 안 잡힘. 허브에서는 "프로젝트 미지정"으로 따로 보여 준다.
2. **사양서는 이름으로만 공장과 이어짐**: NAS 폴더명(예: "기아 화성3공장") ↔ plant.factory("KIA HWASEONG 3") 별칭 표가 필요. 1차는 이름 규칙 매칭 + 못 맞춘 건 '미연결'로 표시, 2차에 별칭 관리.
3. **로봇 마스터가 비어 있는 공장**: GM 부평·동희 0대 등(공정데이터 플랫폼 분석 참고) → 숫자를 그대로 보여 주고 "로봇 미등록" 표시. 지어내지 않는다.
