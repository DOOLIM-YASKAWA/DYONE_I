# 사양서 → 부서(역할)별 확인 항목

사양서 분석의 '부서별 확인' 탭(`SpecDeptReview.tsx`)과 pptx 부서별 장이 쓰는 확인 항목의 근거 문서.
확인 항목·키워드·과거 사고 표시는 코드 `server/src/DyOne.Spec/Dept/DeptChecklist.cs`에 있고, 이 폴더는 그 이유를 적어 둔다.

## 읽는 순서

1. [spec-dept-orgchart.md](spec-dept-orgchart.md) — **종합**: 조직도(부서)마다 하는 일과 사양서에서 볼 것 (2026-10-28)
2. [사양서 부서별 분석.md](사양서%20부서별%20분석.md) — NAS 고객 사양서 여러 건을 부서별로 읽어 정리한 주의 사항·빈도 (2026-10-29)
3. [hs4-spec-team-check.md](hs4-spec-team-check.md) — **견본**: 화성4 신공장 사양서(51쪽) 한 건을 부서별로 직접 읽어 정리한 것. '부서별 확인' 탭이 자동으로 만들려는 결과의 모범
4. [dept-role-mapping.md](dept-role-mapping.md) — 역할 키 ↔ 부서 임시 연결(정식 연결은 '부서 자동 부여' 기능에서)

## 사양서 정밀 분석 (`분석-2026-10-29/`)

| 문서 | 내용 |
|---|---|
| `전수-근거찾기-비율.md` | NAS 고객 사양서 254건(글 있는 233건)에서 확인 항목 키워드가 근거를 찾은 비율 — 고치기 전 기준 |
| `묶음-A1~D.md` | 53건을 7묶음(기아·현대GM·해외·일반산업)으로 나눠 처음부터 끝까지 읽은 부서별 결과 |
| `키워드·항목 반영안.md` | 위 결과에서 뽑은 키워드 추가·오탐 정리·새 항목 31개(코드에 반영함) |
| `반영 결과.md` | 반영 전/후 비율, 거짓 근거 표본 확인, 반영 안 한 것 |

> 종합 문서의 "지체보상 0.1%·세 사양서 동일"은 53건 분석으로 바로잡혔다 — 지체보상은 17/53에만 있고 율도 0.01%~0.1%로 다르다(`사양서 부서별 분석.md`).

## 고칠 때

- 확인 항목을 바꾸면 `DeptChecklist.cs`와 이 폴더의 종합 문서를 같이 고친다.
- 부서 이름은 임시다. 역할 키(`sales.paint`, `pm` …)는 바꾸지 않는다.
