# 조직도별 사양서 중요 항목 (2026-10-28)

## 근거

- **그룹웨어 DB** (SELECT만): 최근 1년 결재 양식·WORKS 앱·출장 품의 → `dept-gw.md`
- **NAS** (읽기만)
  - 부서 이슈·클레임·트러블 → `dept-analysis-A~D.md`, 종합 `spec-dept-focus.md`
  - 연구소·소프트웨어 → `dept-nas-sw.md`
  - 영업·경영·사업기획·교육·해외 → `dept-nas-biz.md`
- **ERP** (dylab, SELECT만): 실행예산 원가 틀·발주·구매품의 → `dept-erp.md`
  - 실행예산의 '공수관리'는 사전준비·모듈라·설치 & 커미션·STAND BY 단계마다 설계·PM/SM·시스템·티칭 공수로 나뉜다. 이 네 역할이 그대로 설계팀·PM팀·소프트웨어팀·어플리케이션팀의 일이다.
  - 공정별 설비 항목(ROBOT·OPENNER·BELL·GUN·CCV·FGP·Embedded·모니터링)은 사양정리 행과 1:1로 맞는다.
  - 발주는 전부 구매팀이 한다. 로봇은 거래처 3곳(장납기), 구매품은 거래처 138곳이다.

## 공통 원칙

- 사양서 접수는 영업, 사양정리 작성은 PM이 맡는다. 부서 요약은 영업 → PM → 각 부서 순서로 전달한다.
- 사양서는 고객사가 달라도 같은 틀을 쓴다(광주2 V6·울산51·인도 MP2). 그래서 조항 → 부서 연결 규칙을 한 번 만들면 계속 쓸 수 있다.
- 사양서에 **없는데** 사고가 잦았던 항목은 "확인 필요"로 해당 부서에 보낸다.
  - 대상: 에어 실측값, 엔코더 공급 주체, L/S 위치, 스페어 범위, 품질 기준, 반입로

## 사양정리 초안 반영 제안

1. **부서 꼬리표**: 사양서 조항과 사양정리 행에 받을 부서를 붙여 '부서별 요약' 장을 자동으로 만든다(위 목록이 연결 규칙).
2. **새 행·장 추가**
   - 교체 공사의 '기존 대비 변경점'
   - '상업 조건' 장: 보증·검수·지체보상금·인도조건·제출서류. 재무·CS·영업용이고, 지금 사양정리에는 없다.
3. **확인 필요 목록**: 사양서에 없지만 사고가 잦았던 항목은 부서별 "확인 필요"로 보낸다.
4. **ERP 실행예산 항목 연결**: 사양정리 행마다 ERP 실행예산 항목을 붙인다(예: Robot → ROBOT·OPENNER / Stand by → 공수관리 STAND BY_설계·PM·시스템·티칭 / Training → 교육(CS)).
   - 영업 견적, 실행예산, 부서별 요약이 같은 틀이 된다.
   - 부서는 실행예산 항목을 보고 "내 공수·내 예산에 걸린 조항"을 바로 안다.
5. **부서 확인**: 부서 이름·담당은 그룹웨어 결재·앱 기준이다. 개편 전 이름이 섞여 있고 일부는 추정이라 각 부서 확인이 필요하다.
