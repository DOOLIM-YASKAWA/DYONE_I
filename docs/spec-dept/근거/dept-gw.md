## 공통 관찰

- **프로젝트 코드가 모든 업무의 축**: 출장 품의서 제목이 `DLP-26-xxx (수주) / 이름 / 날짜` 형식이라, 출장 = 특정 수주 프로젝트 현장 투입으로 바로 연결됨. `DL-26-000`은 공통/비프로젝트 코드로 추정.
- 실행예산보고서 제목 형식: `DLP코드 / 프로젝트명 / 고객사 / 담당`. 프로젝트 입찰 보고서는 `[DLP코드] 프로젝트명`.
- 게시판: 부서 게시판은 사실상 미사용(테스트·익명신고 몇 건). 전사 게시판(공지사항 125, 경조사 29, 경영공지 17건/1년)만 활동 → 부서 업무 파악에는 쓸모없음.
- 업무보고(report) 폴더: 과거 PM팀 일일업무일지(14,119), 호남·영남지사 일일업무(4,146/2,817), 어플팀 일일업무일지(6,676) 등이 있었으나 최근 1년 신규는 중국 법인 `YDB_Weekly`(258)만. → 현재는 결재·WORKS 앱으로 옮겨간 상태.
- 업무(task) 폴더: 데이터 없음.
- WORKS 전사 공통 앱(부서 구분 불필요): 2026 전사근무관리(20,690/1년), 차량유류대, 출장결과보고(3,732), 출장현황(1,130), 수주내역 조회(CS)(2만여 건, 시스템 연동으로 추정), 화성 식수 관리, 법인카드 지출결의(앱 608, 8,257).

### 한계
- WORKS 앱 문서 중 상당수(수주내역 조회, 발주진행현황, 출장결과보고 등)는 작성자가 퇴사자/시스템 계정이라 부서 귀속 불가 — 연동 자동 생성으로 추정.
- 겸직자는 첫 번째 소속 부서로만 집계(앱 작성자 매핑).
- 앱 문서의 실제 값(EAV `go_applet_vals`)은 이번엔 열지 않음 — 필드 구성만 확인.
