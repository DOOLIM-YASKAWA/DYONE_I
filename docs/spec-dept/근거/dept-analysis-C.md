## 4) 부서별 "사양서에서 꼭 봐야 할 항목"

### 4-1. 소프트웨어팀(제어) — 사양서에서 꼭 확인
1. **PLC 메이커·CPU 모델 지정 여부** — 고객별로 Mitsubishi(Q26UDV, 광명2)·AB(HMGMA)·Siemens S-Cube(르노)·LS로 다름. 매뉴얼·레이아웃이 4종으로 나뉘어 있음. → System
2. **필드버스/네트워크 방식** — CC-LINK IE·CC-LINK·Profinet 등, 링 구성 요구, CPU 간 광통신, 케이블 종류(FTP Cat5e, 80m 넘으면 광), 존당 스테이션 수 제한(S-Cube 30 스테이션). → System
3. **MES·상위 시스템 인터페이스** — 차종/컬러/옵션 수신, 생산·알람 실적 전송, 전용 통신카드 수(광명2: MES용·차량정보용 2개), IoT 플랫폼 데이터 규격(VIN 기준 로깅, 타임서버 동기화, 2년 보관, 알람 1:1 접점 매핑). → System
4. **인터록 대상과 방식** — 컨베이어·부스팬(버너 ON 신호)·소화설비(이중화 여부)·믹싱룸/PCS·실러룸, 하드와이어 여부. → System, PCS
5. **컨베이어 조건과 신호** — 연속/Stop&Go, 엔코더 공급 주체, 바디(지그) 피치와 균일성, UPH, 컬러체인지 시간 → 트래킹 센서·IDLE/뮤팅 위치 계산의 입력값. → Basic Condition
6. **안전 구성** — 방폭/비방폭 구역(포토센서 5점 vs 라이트커튼), 비상정지 개수·위치, 세이프티 락·안전문, 안전 2채널. → Others(안전펜스), System
7. **전원·전장 규정** — 메인/제어 전압, VSP·TR·**UPS/AVR 허용 여부**, 접지(1차 접지 공급 주체, 1종 10Ω), 케이블 색상·단면적·라벨, **지정 전장품 메이커 목록**. → Utility, Panel
8. **HMI·PC·모니터링 요구** — HMI 메이커, PC 사양·대수(마스터 PC, 비상 대응 PC), 표시 언어, 로봇 실시간 모니터링 서버, 원격 접속 허용 여부(원격지원 매뉴얼 보유). → Panel(OP), System
9. **스페어 파트 범위·수량** — B&B 압력변·유량변, AOPR, 스월 케이블 등 현장 스페어 부족이 반복 이슈. → 기타사항 체크리스트
10. **제출물·교육** — 준공도면(CAD+PDF), 백업, IO 리스트, 파라미터 리스트, 데이터 명세서, 교육 확인서. → Training, Others

### 4-2. 공정품질실(어플리케이션·공정검토) — 사양서에서 꼭 확인
1. **차종 수·바디 제원·옵션(LHD/RHD)·신차 일정** — 교육 플랜 첫 단계가 "신차 사양서 확인, 공정도 확인, 부스 레이아웃 구성". → Body Size, Schedule
2. **UPH·바디 피치·부스 길이/높이/폭·존 구성** — 시뮬레이션으로 로봇 대수와 부스 길이를 줄인 사례(13→12대, 16m→13.5m). → Robot, Booth size, Basic Condition
3. **컬러 수·컬러체인지 시간·도료 종류(수용성/유용성)** — C.C TIME OVER 알람, 컬러 데피니션 오류, 이색 사례. → Color(CCV), Paint
4. **오프너 로봇 사양과 오프너–페인트 로봇 신호 체계** — 신차 대응 이슈 대부분이 오프너 티칭·L/S. → Robot
5. **디그레이드 요구 수준(UPH 유지/감소)** — 광명2 요약표에 공정별 "디그레이드(UPH =/↓/?)"가 따로 표시됨. → Robot, Basic Condition
6. **비전(3D Measuring/Capmes) 유무** — 교육 1주 분량을 차지. → System/Others
7. **티칭·이벤트·양산 대응 기간과 인원(M/D)** — 사양서의 "시험생산 대응·양산 이후 대기(예: 2명×3개월 주야)" 조건. → Stand by, Schedule
8. **모듈라(OLT) 기간 확보** — "모듈라 기간 충족 필요, 영업 협의". → Schedule

### 4-3. 기술지원팀(품질관리/도료) — 근거 있는 항목만
1. **PCS 공급 조건** — 자동기 스테이션 압력(100~120psi), 순환 방식, 온도 조절. → PCS
2. **D.I Water 등 세정 유틸리티 압력**(수용성) — EVO 이색 사례 근거. → Utility
3. **고객 보전·제조 교육 범위**(프로젝트별 교육 과정) — 품질관리팀 월간 업무. → Training

### 가장 중요한 이슈 패턴
1. 현장 스페어 부족(B&B 압력변·유량변, AOPR) → 조치 지연 반복
2. 바디/지그 피치·컨베이어 엔코더·스타트 L/S 문제 → 충돌·티칭 지연
3. 도장기 세정 시퀀스를 다른 프로젝트 것으로 적용 → 이색·Overfilling
4. 세정 유틸리티(D.I Water) 압력 부족 → 이색
5. 케이블·호스 간섭·마모(스월 케이블, 덤프 호스, 엔코더 케이블) → 토출 불량·알람
6. 모듈라에서 놓친 항목(호스 누락, 방폭에어 미연결) → 현장 트러블
7. 신차 대응: 오프너 L/S·신호 타이밍, 컬러 데이터 입력 오류, CC 시간 초과
8. 디그레이드 운영(1대 고장 시 스타트 변경) 알람·절차 미숙
9. 고객 지정 PLC·네트워크·전장품·IoT 데이터 규격이 프로젝트마다 다름
10. 시뮬레이션·모듈라가 부족하면 현장 대응 기간이 늘어남(공정품질실 자체 진단)
