### 2-4. 2026 하계 공유회의 '진행 단계' 정의 (v6 > 임베디드 Presentation1)
초기검토 → **사양서** → 킥오프 → 승인 → LAB TEST → OLT → 설치 → 시운전 → 마무리
- 설계 승인: 킥오프 자료(마스터 스케줄·교육 일정·레이아웃·장비 소개·**사양 리뷰 자료**·사전공사·협의사항·반입로), 설계 자료(**하중 검토·유틸리티 계산식**·제작품 리스트·현장 도면)
- 출고 승인: LAB TEST 결과, 강건화·실패 사례 개선 적용, 검수 회의록 반영 여부, 스페어 파트 리스트
- 운영 승인: 설치 데이터(투입 MD·체크시트·공사일지), 시운전 데이터(로봇 잡·유량 테스트·토출량)
- 최종 승인: 최종 도면(기계·전기·PCS), 스페어 인수인계, 교육 보고서, 펀치 완료

### 2-5. 일반산업(턴키) 개별 발주 R&R 제안 (v6 > Presentation3 > ECO 임베디드 > 슬라이드 2)
- DY 영업: 대외 영업, **사양 정립**, 기술제안 정리, 견적·입찰·수주, 수주 설명회
- DY 기술 PM: 프로젝트 이해·정립·리딩, 집행 예산 확인, **사양 정립**
- 어플: 프로세스 이해, 기술 검토 Simulation / 시스템: 도면 개요·협력사 관리·시운전 / 설계: 레이아웃(구상설계 TBD)
- 협력사 A(설계)·B(기계)·C(제어)·D(어플): 사양 상세 검토·견적·제작·설치·티칭. 협력사 선정은 구매·기술·영업이 업체 평가

### 2-6. As-Is 체계도에 정리된 부서별 이슈 (As-Is 체계도, 이슈/요구사항 표)
- PM: PM마다 절차가 다름, 구성원이 사양을 모름, 영업 단계 내용이 구두로만 전달됨 → 요구: **"명확한 사양 정리 SHEET 작성 - PM"**, 영업 단계 내용은 회의록이나 문서로 전달
- 영업(수주 설명회): "수주 설명회 하고 실제 고객 요구 사양 다름 / 이면계약이 있으면 기술부에 회의록 전달 필요"
- 모듈라: 사전공사 체크 미흡으로 본공사에서 어려움이 생김, 설계 후 도면을 검증하지 않아 오류 발생(예: 호스 누락) → 도면 검도 프로세스 필요
- 현장: 주변 설비 간섭 등 체크 미흡, 현장 I/O 오류 → 어플·품관팀이 미리 현장 점검(현장 품질, 세부 시운전 조건)
- 회의 결론: "입찰사양서 작성, 특히 기술검토 부분에 기술부가 적극 참여해야 함" / "기술검토 미비 → 영업실행 → 기술실행 → 자재·구매·인원"으로 위험이 넘어감

1. **사양서의 스페어·추가 항목(SPC·케이블·Stand-by PC 등)을 사양정리에 모두 옮기고 PM에게 문서로 넘기기**. 동희 스페어 SPC·케이블 누락, 화성2 킥오프 펀치 34건, As-Is "구두 전달 지양·회의록 전달" 이 근거임.

3. **공급 범위·공사 범위(기계/전기/PCS/판넬룸 에어컨/철거품 처리)를 견적·발주 전에 확정하기** (GMK 부평 "현장 체크 후 누락 없게 견적 반영", 화성4 업체 범위).
