# 사양 판 흐름 — 사양서·사양정리가 바뀔 때 (설계안, 2026-10-30)

사용자가 원하는 흐름(10-30):
1. 사양서를 올린다 → 사양정리 초안을 만든다 → 부서별로 중요한 부분을 정리한다.
2. 사양서가 바뀐다 → **이전 사양서와 비교**한다 → 그걸로 사양정리를 다시 만든다.
3. 이후엔 사양정리만 계속 바뀐다 → **이전 사양정리와 비교**한다.

비교는 같은 종류끼리 한다(사양서↔사양서, 사양정리↔사양정리). 여기에 "사양서에서 바뀐 값이 사양정리에 반영됐나"를 맞춰 보는 확인을 더한다. 근거 분석은 [이력·판 비교·AI 역할 2-4장](이력·판%20비교·AI%20역할%20(2026-10-29).md).

## 지금 있는 것 / 없는 것
| | 있음 | 없음 |
|---|---|---|
| 1단계 | 사양서 업로드, 사양정리 초안(사양서 **파일 하나당 초안 하나**: `_spec/drafts/{프로젝트}_{파일}.json`), 칸 수정 기록(`Edited`·`EditedBy`), 부서별 확인 탭, pptx 내보내기 | 초안을 "rev1"로 확정해 두는 것 |

| 3단계 | 사양정리 pptx를 칸으로 읽는 코드(`SpecItems.ReadSheet`, NAS 라이브러리용) | 사양정리 판 저장, 판끼리 칸 비교, 사양서와 어긋난 칸 경고 |

## 화면 흐름 (안)
프로젝트 '사양' 화면 위에 **판 줄기**를 하나 둔다.

```
사양서   V1 ──────────── V2 ─────────────────
           │               │
사양정리  rev1 ─ rev2      rev3 ─ rev4 ─ rev5
```
- 사양정리 판마다 "어느 사양서 판으로 만들었는지"를 붙인다(rev3·4·5 = V2 기준).
- 두 점을 고르면 비교가 열린다. 같은 줄끼리만 고를 수 있다.

### 1단계 — 처음 (거의 지금 그대로)
- 사양서 V1 업로드 → 초안 → 부서별 확인.
- 새로 추가: **[rev1로 저장]** 버튼(또는 pptx를 내려받을 때 자동). 그때의 칸 값을 그대로 얼려 둔다.

### 2단계 — 사양서가 바뀜
- 같은 프로젝트에 사양서를 또 올리면 "**이전 판(V1)이 있습니다 — 비교할까요?**"를 띄운다.
  - 판 묶기: 같은 프로젝트·'사양서' 분류이고 이름에서 V/rev/날짜를 뗀 줄기가 같은 파일. 사용자가 직접 고를 수도 있다.
- **사양서 비교 화면 = 핵심 항목 14개 표**
  - 항목 / V1 값 / V2 값 / 쪽 / 걸리는 부서. 안 바뀐 항목도 "그대로"로 보여 준다.
  - 그 밖의 변경은 맨 아래에 접어 둔다.
- **부서별 확인도 판 비교**: V2에서 새로 생긴 확인 항목, 없어진 확인 항목, 근거 문장이 바뀐 항목을 부서별로 표시한다.
  - 예: 구매팀 — "세이프티 PLC → 세이프티 릴레이" 바뀜
- **[V2로 사양정리 만들기]**: 빈 초안이 아니라 **마지막 사양정리(rev2)를 이어받는다**.
  - 사람이 고친 칸과 모델 결정은 그대로 둔다.
  - 핵심 항목이 바뀐 칸만 새 값으로 바꾸고 노란색으로 표시한다("V1→V2: 11.5m → 9.5m").
  - 사람이 고친 칸인데 사양서가 바뀐 경우는 덮어쓰지 않는다. 그 칸에 `⚠ 사양서 V2에서 바뀜 — 확인`만 단다.

### 3단계 — 사양정리만 바뀜
- 사양정리 판이 생기는 길은 둘이다.
  - ① 앱에서 칸을 고치고 [새 판으로 저장]
  - ② 영업부가 pptx를 직접 고쳐 올림. 이때는 `ReadSheet`로 칸을 읽어 판으로 저장한다.
- **사양정리 비교 = 칸끼리**: Robot·Booth size … Others 줄마다 rev4 값 / rev5 값을 둔다. 바뀐 칸만 강조하고, 누가 언제 고쳤는지도 보여 준다.
- **늘 켜 두는 확인 — 사양서와 어긋난 칸**: 최신 사양정리 값이 기준 사양서 값과 다르면 표시한다.
  - 예: 아산 rev7 60Hz ↔ 사양서 50Hz
  - 고의로 바꾼 것이면 "확인함(사유)"으로 끈다.

## 바뀐 뒤 부서에 알리기 (안)
**지금 있는 것** (2026-10-30 확인)
- 앱 알림: 종 모양 알림함과 실시간 푸시(SignalR `NotificationHub`, `NotificationService.PushAsync`). 지금은 그룹웨어 변경 알림(`sync.change_notice`)만 보낸다.
- 프로젝트 인원 `project.project_member`(역할·업무). 로컬 기준 15명·3개 프로젝트뿐이다.
- 부서별 확인 항목(`DeptChecklist`)이 이미 사양정리 칸과 이어져 있다. 바뀐 칸에서 알릴 부서를 바로 정할 수 있다.
  | 칸 | 부서 |
  |---|---|
  | Robot | 설계팀·PM팀·구매팀·어플리케이션팀 |
  | Utility | 설계팀·호남·영남지사 |
  | Panel | 설계팀 |
  | System | 소프트웨어팀 |
  | Stand by | PM팀·지사 |
  | Schedule | PM팀 |
  | Atomizer·FGP·Color | 모듈라팀(+구매·해외법인) |
  | Training | 교육실 |

**흐름**
1. 영업부가 사양정리 새 판을 **저장할 때만** 알린다. 칸을 고칠 때마다 알리지 않는다.
   - 저장 창에 "알릴 부서" 미리보기를 띄운다. 바뀐 칸에서 자동으로 고르고, 영업부가 빼거나 더할 수 있다.
   - 오탈자만 고친 판은 "알리지 않음"으로 저장할 수 있다.
2. **부서마다 한 건씩**, 그 부서와 관련된 칸만 담아 보낸다.
   - 예: 설계팀 "[DLP-25-274 아산] 사양정리 rev7 — Utility 50Hz→60Hz (⚠ 사양서와 다름), Panel AP 4→2"
   - 링크를 누르면 사양정리 비교 화면이 그 부서 칸만 걸러진 채로 열린다.
3. 받는 사람: 프로젝트 인원 중 그 부서 사람 → 없으면 그 부서(역할) 전체.
   - 부서 → 사람은 dept-auto-assign 설계(역할 키)와 맞춘다.
4. **부서별 확인 상태**: 판마다 부서별로 `확인 대기 / 확인함`을 둔다. (부서 질문·댓글은 2026-10-30 사용자 요청으로 뺐다.)
   - 영업부·PM은 판 줄기에서 "rev7: 4개 부서 중 3곳 확인"을 본다.
5. 며칠(예: 3일) 지나도 확인하지 않은 부서에 한 번 더 알린다.
6. 사양서 새 판이 들어왔을 때도 같은 방식이다. 이때는 핵심 항목 변경을 '부서별 확인 변화' 결과대로 알린다.

**결정할 것**
- 알림 기록을 어디에 쓸지: `platform.notification`은 지금 쓰기 허용 범위(`org.*`·`project.project`·`sync.*`) 밖이다. 새 표를 만들면 DEPLOY 문서도 갱신해야 한다.
- 그룹웨어 메일·메신저로도 보낼지: 지금 그룹웨어는 조회 전용이라 따로 승인이 필요하다. 처음엔 앱 알림만 쓴다.
